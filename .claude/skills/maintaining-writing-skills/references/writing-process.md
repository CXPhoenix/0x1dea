# 按任務進入寫作流程

這是 0x1DEA 為寫作任務採用的流程參考，作者聲音仍由 phoenix-writing 決定。安排新文、補來源或跨次作品時讀所需分支；普通潤稿從修訂進入，單次解釋直接說明，不為每篇文強制跑相同結構。來源與取捨見 [SOURCES](../../../../maintenance/writing-skills/SOURCES.md)。

## 規劃與專案脈絡

從可見脈絡確認讀者的先備知識與目的、文章要完成的事、文類、來源、限制與授權。合理假設標為假設；缺少會改變結果的資訊才問，已清楚的範圍繼續完成。完成條件是這些欄位已確定或明示假設，能據以寫稿。

獨立寫作專案（短稿也可成立）建立或沿用其 CONTEXT.md 與 PROJECT.md；普通單次解釋不建立虛構專案。本地 Codex 使用專案實際檔案，確認是否寫入成功，不能照搬 ChatGPT 原文的「未保存、下次上傳」說法。這次技能維護的任務由 openspec 追蹤，不另外造文章專案。

CONTEXT.md 只存詞彙：術語、定義、適用語境、別名／英文、必要來源。需求、讀者設定、作者決策、待解問題與下一步放 PROJECT.md 或專案既有任務文件。沿用已有 CONTEXT-MAP.md，不混入技能自己的詞彙表。詞義衝突先辨認是否適用範圍不同；需要作者決策時保留舊定義並詢問，不把推定決策標成使用者已確認。

## 撰寫與文類

依段落功能安排內容；將事實、假設、作者判斷分清楚。完成稿覆蓋本次要求，若有阻礙，先寫完不受影響的部分，再獨立揭露缺口。

- 教學：按整堂課或核心觀念建立方向、目的與理解檢查，術語與因果逐步說清楚。學習目標不是已證明的學習成果。
- 技術教學：交代前置條件、目的、機制、預期結果、重要失敗條件和限制；故事不遮住操作相依。
- 正式文件：保留確切數字、日期、角色、義務與模板功能，區分提案、已確認安排和待核准。指定模板的摘要、說明與請求各有功能，不因風格而刪掉。

轉折、預告、回顧與呼應依它服務的尺度選擇：段落、章節、全文、整堂課或核心觀念。保留幫助讀者定位與鞏固的重複，修掉沒有新增內容或功能的自我複述；不用研究統計當配額，也不以作者是否像人作評分。

## 修訂與交付

普通潤稿可以修句與重排，保留意義、範圍、立場、不確定性和有效作者聲音。全文改寫已獲授權就完成，不再請求同一項批准。重大未授權內容新增或立場改動，先說明需要作者決定的部分；證據不支持結論時揭露缺口，讓作者選立場。

材料疑點用可用權威來源核對並記錄引用；未取得的證據標為未驗證。引用格式依文類與使用者要求選，不按引用數量固定切換格式。

圖表用於幫助理解：正文直接說明圖表呈現的機制、關係、證據與限制，讓論述自然承接，圖說交代範圍。一般文章不以移動視線的操作導語替代論述；明示要求操作式讀圖教學時才逐步導引。不規定提問開場，也不禁止讀者對話。製圖 prompt 留在製作資料或使用者要求的附錄，不自動塞進正文。實際圖片／文件能力缺少時交代限制，不能把製作指令當成已製作的成品。

解釋降低呈現難度時，仍保留成立條件、不確定性與重要例外。若需要原句與改寫的精確對照，可詢問是否要比較表，記住本專案的選擇，不每輪重問；對照表要有實質映射，不複製每句。

自檢事實、數量、標籤、立場、詞彙一致性、語言、格式與範圍；普通修訂不自動升級完整多人稽核。正文與任務進度、理由、阻礙分開。完成條件是交付完整文字與必要缺口，不強制附報表或固定回顧。
