# P13 前置修正票提案

本輪僅提出四票 A–D，待使用者確認；代號不是正式 ticket id，尚未寫入 tracker。T-0016 維持 `review`，原 P13 仍未執行。原 spec、24 項測試分配與歷史驗證契約不改寫。

| 代號 | 範圍與可驗收交付 | 阻擋關係 | 本機測試計畫列 |
|---|---|---|---|
| A | 讓核准的 workflow 以精確路徑、模式及雜湊進入共同工程 successor；未核准內容仍拒絕 | 無 | PA-01–06，共 6 列 |
| B | 可重現的 runner 前置檢查、外部設定交付與狀態接續；缺少環境或授權證據便停止 | 無 | PB-01–06，共 6 列 |
| C | 將可信驗證結果綁到指定 PR head；head、staging、main 或 policy 漂移便撤銷舊就緒判定 | A、B | PC-01–07，共 7 列 |
| D | 以明確核准紀錄接續指定手動 PR 歷史，不冒充自動化擁有權 | 無 | PD-01–04，共 4 列 |

共 **23 列新提議的本機前置測試**，尚未核准、撰寫或執行。一列包含列明的正反案例，不等於單一 assertion。原 P13 的 a–l 共 12 個遠端演練子案例維持 **NOT RUN**，不能拿這 23 列取代。

可獨立開始的前緣為 A、B、D，C 等 A、B 完成。P13 恢復前，四票須完成核准的工程落地，且測試 repository、runner、權限及演練範圍另經授權。四票不依賴 T-0016 `done`，避免循環阻擋。

確認後重新掃描全專案最大 ticket id，才依序配置正式票號。本輪不預留票號、不改 T-0016 或 T-0017／T-0018 的狀態與阻擋欄位。若同意本提案，正式寫票時提議在 T-0016 保留既有依賴，另加 C、D 為未完成前置；A、B 由 C 間接阻擋。這項圖形更新也在本次待確認範圍內。
