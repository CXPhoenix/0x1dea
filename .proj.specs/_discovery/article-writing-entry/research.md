# 文章起始 skill：寫作探索、術語與公開發表的研究評估

查核日期：2026-10-24（Asia/Taipei）。本機基準：`6fcb277a9841dfad21d91f79005d39924acd92d2`。

本文件是研究與設計建議，不是已核准 spec，也未修改既有 skill、工程流程、文章或發布設定。外部研究由主執行緒與一位唯讀 research agent 分工查閱；本文件由主執行緒整合保存。沒有執行新 skill 或進行效果測試。

## 結論與已確認偏好

建議增加一個文章專用的起始 skill，暫稱 `article-discovery`，借用 `grill-with-docs` 的組合思路，但不直接串接現有兩個 skill 的全部指令。原始 `grilling`、`domain-modeling` 保留作工程用途；文章入口採取適合寫作的釐清方式與按需術語整理。

使用者已確認預設互動方式：**先自由聊，有需要才整理設定**。這是使用者決策，不是研究推論。

新入口的任務是幫助作者找到下一個可寫的動作，容納目的尚未形成、只想抒發、沒有指定受眾、文體混合與刻意留白。不以完成問卷、確立中心論點、產生詞彙表或承諾讀者成果作為所有文章的起稿門檻。

重要區分：文章的創作流程與工程交付流程可以分開設計；新增或修改 skill 本身仍是專案維護工作，須遵循現有需求、spec、票與驗證規則。本次研究沒有使任何工程關卡失效。

## 二、外部證據與遷移界限

### E1：寫作目的會在寫作中生成

Flower 與 Hayes 的原始論文將規劃、轉寫與檢視視為可以彼此嵌入的過程，也指出作者會因寫作所得而改變主要目標或建立新目標。這支持允許返回探索與修改方向，不支持「必須先沒有目的」，也不是對新 skill 的效果驗證。已讀原論文 pp. 366–369。

來源：Linda Flower、John R. Hayes，1981，[A Cognitive Process Theory of Writing（原論文掃描）](https://www.lirvin.net/1301sitebb/FlowerHayesCognitiveProcessTheory81.pdf)；[出版識別 DOI](https://doi.org/10.58680/ccc198115885)。原始研究年代久遠、使用特定寫作任務，不能直接當成今日繁中個人 blog 的實驗結果。

### E2：自我表達也是完整的寫作目的

NCTE 的正式立場文件明確涵蓋個人表達與實用寫作，並承認寫給自己的作者也是自己的受眾。對 skill 的設計推論是：接受「寫給自己」「想留下感覺」為有效答案；不必把它翻譯成教學目標。這是寫作教學的專業指引，並非某套訪談法的因果試驗。

來源：NCTE，2018-11-14，[Understanding and Teaching Writing: Guiding Principles](https://ncte.org/statement/teachingcomposition/)，Principles 1.1–1.2、2.1、3.3。

### E3：個人 blog 的動機可以混合

Nardi、Schiano 與 Gumbrecht 的民族誌研究記錄生活更新、意見交流、藉寫作思考與情緒表達等動機，並指出它們不互斥。樣本是 23 位、主要位於特定美國社群的作者；研究發表於 2004 年，不能推估目前 blog 各種動機的比例，也不能據此宣稱抒發具有治療效果。

來源：[Blogging as Social Activity, or, Would You Let 900 Million People Read Your Diary?](https://artifex.org/~bonnie/pdf/Nardi_blog_social_activity.pdf)，CSCW 2004，Methods、§4.3，印刷頁 223、225。

設計推論：互動強度與文類要分開。技術文章也可能在探索，抒情文章也可以要求嚴格修訂；不能依文章標籤自動分配問卷。

### E4：作者想像的讀者與實際讀者可能不同

Marwick 與 boyd 的質性研究討論想像受眾與脈絡合流，並記錄把發文當生活紀錄與自我表達的參與者。研究對象是當時的 Twitter，遷移至 blog 是跨情境推論。由 research agent 成功開啟全文；主執行緒重讀此 URL 未成功，未據此增加更細的全文主張。

來源：2011，[I tweet honestly, I tweet passionately: Twitter users, context collapse, and the imagined audience](https://www.tiara.org/wp-content/uploads/2018/05/Marwick_boyd_TweetHonestly.pdf)，pp. 115–119，DOI 10.1177/1461444810365313。

boyd 另整理持續留存、可複製、潛在擴散、可搜尋與不可見受眾等特性，並區分潛在高能見度和保證有人閱讀。這是社群網站分析框架，不是 blog 一定大量曝光的預測。

來源：2010，[Social Network Sites as Networked Publics（作者 draft）](https://www.danah.org/papers/2010/SNSasNetworkedPublics.pdf)，draft pp. 7–11。

設計推論：把創作時想對誰說話，與公開前願意讓哪些內容離開原始脈絡，分成兩個時機處理。公開可見不代表作者必須迎合所有可能讀者。

### E5：術語協助不等於每篇需要正式詞彙表

W3C 的 SC 3.1.3 解說允許依目標受眾判斷特殊用語，並列出行內定義、連結與詞彙表等方法。它是 AAA 條件，Understanding 是非規範性解說；不能說成所有網站的 A／AA 共同門檻。

來源：[Understanding SC 3.1.3: Unusual Words](https://www.w3.org/WAI/WCAG22/Understanding/unusual-words.html)，Intent、Examples、Techniques。

設計推論：只有會影響理解或論證的技術詞、作者自訂詞、混淆用法需要整理。抒情的多義詞與比喻可以保留模糊；不能把「失敗」「自由」「累」一律操作化為唯一標準定義。內部術語一致與讀者需要的白話解釋也應分開。

### E6：公開網頁的閱讀支援可以晚於起稿

W3C 建議可辨識內容的頁面標題、語意結構、有意義的連結文字、適當媒體替代內容。圖片替代文字依資訊、功能或裝飾用途而定；複雜圖表需要其他可取得的說明。

來源：[Writing for Web Accessibility](https://www.w3.org/WAI/tips/writing/)（頁面標示小幅更新 2024-07-16）；[An alt Decision Tree](https://www.w3.org/WAI/tutorials/images/decision-tree/)（2024-05-13）。兩者由 research agent 查閱。

設計推論：將此放入編輯與發布準備，不要求每首詩、每則短札都在起稿前規劃摘要、小標題與圖表。指引本身也不等於完整的網站無障礙驗證。

### E7：證據出處與素材使用條件是兩件事

Creative Commons 的署名建議以作品、作者、來源與授權整理資訊，並依實際授權與修改情況交代。它不能推導成「只要附來源就能使用任何素材」。

來源：[Recommended practices for attribution](https://wiki.creativecommons.org/wiki/Recommended_practices_for_attribution)，由 research agent 查閱。

設計推論：有引文、圖片或他人材料時先保留來源；準備公開時再整理必要標示。不將每次自由寫作變成授權問卷；本研究不提供個案法律判斷。

### E8：搜尋目標需要作者選擇

Google 的 people-first 文件討論搜尋系統中的內容品質，明確否認偏好特定字數，也反對為了看似新鮮而改日期。它不是所有個人寫作價值的通用標準。

來源：[Creating helpful, reliable, people-first content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content)，搜尋導向內容與 Who／How／Why 區段。

設計推論：搜尋能見度是可選需求；不用 SEO、字數或讀者完成任務衡量純抒情文字。技術資訊仍要核對版本、日期、前置條件與證據範圍，這不必依賴 SEO 才成立。

### E9：AI 支援需要保留作者的決定權

Hwang 等人的研究透過 19 位專業作者訪談與共同寫作、30 位讀者調查，討論真實表達與個人化支援。研究將作者的經驗與創作過程納入，而不只考慮生成文字是否像作者。這是有限樣本的質性／探索性研究，不能證明個人化工具必然保住作者聲音。

來源：[It was 80% me, 20% AI: Seeking Authenticity in Co-Writing with Large Language Models](https://arxiv.org/html/2411.13032v1)，2024-11-20 preprint，§3、§4.2–4.4、§5.5；本文依此版本，不以頁面未定稿的 conference metadata 作正式出版證明。

設計推論：入口應能問清楚作者現在要的是陪聊、提問、回應、組稿或挑戰論點；不能默認作者每次貼文字都希望被批判與改寫。也不能替作者發明經歷、替情緒補上心理原因，或自動寫出作者沒有選擇的和解與勵志結尾。

## 三、三種實現方向

| 方案 | 優點 | 代價／風險 | 評估 |
|---|---|---|---|
| 原封不動組合 grilling＋domain-modeling | 新增內容最少，沿用既有決策方法 | 完整收斂條件、積極消除模糊、程式碼與 ADR 契約會被一起帶入；對自由寫作容易過度提問 | 可用於作者明確要求的嚴格論點討論，不適合預設入口 |
| 新增文章入口，改編提問與術語原則 | 能明確容納留白、試寫與不同協助強度，與工程入口分開 | 必須清楚界定觸發與停問條件，避免重複既有寫作指引 | **建議**；只增加一個入口，詳細分支按需讀取 |
| 全部放進 Phoenix | 容易從既有風格技能找到 | 將作者風格、創作探索、一般寫作及文件管理綁在一起，其他文體也被迫載入 Phoenix | 不建議；保留聲音與流程分工 |

不建議為了形式對稱再建立三個互相呼叫的完整技能。最小可行方向是一個起始 skill，引用短篇的訪談／術語參考。名稱、檔案位置、跨 runtime 包裝與實際指令文字尚未定案。

## 四、建議的互動契約

### 預設：自由聊，按需整理

1. 先接住使用者提供的句子、事件、困惑或材料。已有足夠脈絡就回應或試寫，不先送出設定表。
2. 提問只針對會改變下一步的資訊，沿用已回答內容。作者可以回答「不知道」「先不決定」「這就是要留白」。
3. 有助下一步時，整理一小段暫定方向，作者可以直接修正；不反覆要求確認同一件事。
4. 允許開始寫、返回探索、改受眾或改文體。新資訊只更新受影響的選擇，不重跑訪談。
5. 結束條件是已有下一個可寫的動作，或作者要開始寫；重要未定事項可帶著走。若作者只想把話說完，交付可以是原話整理，也可以保持原樣。

「先寫一段」是可選工具，不是固定練習。完整 grilling 只在作者要求嚴格推敲時啟用，也不把純審美偏好偽裝成事實問題。

### 合作強度可以途中改變

| 當下需求 | 適合的協助 | 不應強制補齊 |
|---|---|---|
| 想抒發或記錄 | 聽、回應、保留片段與語氣；依要求整理 | 中心論點、讀者收穫、詞彙表、正向結論 |
| 邊寫邊想 | 對照材料、找疑問、提出少量試寫方向；觀點可暫定 | 一開始就選定立場與固定大綱 |
| 教學、解釋或論證 | 確認先備知識、用途、機制、證據、限制與概念區分 | 不相關的情緒自白、完整領域模型 |

這些是互動方式，不是互斥文類；一篇文章可以同時包含經驗、技術說明與抒情。

### 按需整理的文章設定

| 設定 | 用途與可接受狀態 |
|---|---|
| 寫作起點 | 一句話、一段材料、一件事或一種感覺就足夠 |
| 創作意圖 | 解釋、說服、記錄、探索、抒發，或尚未形成 |
| 受眾 | 先備知識、共同經驗；也可以是自己、少數熟人或不指定 |
| 文體與聲音 | 散文、隨筆、技術教學、評論或混合；Phoenix 需明示或延續既有作品 |
| 本篇想保留的東西 | 一個場景、一句話、怒氣、幽默、矛盾、閱讀節奏 |
| 範圍與深度 | 想處理什麼、暫時不展開什麼；無須宣稱涵蓋一切 |
| 術語與解釋 | 有理解風險才整理；定義、比喻與作者自訂用法分清楚 |
| 來源與主張 | 親身觀察、可查證資訊、假設與作者判斷；無外部主張不硬補引用 |
| 協助方式 | 陪聊、提問、回饋、組稿或挑戰，可依當下切換 |
| 公開範圍與搜尋需求 | 準備公開或作者主動在意時處理，避免搶占起稿注意力 |

每項可以標示為已確認、暫定、刻意留白或不適用；這是辨認狀態，不是要求先完成四種標籤。沒有專有名詞就不建立空表，也不把情緒詞轉為全站詞彙定義。

## 五、公開 blog 的檢查時機

起稿時優先服務表達；草稿形成後依內容做必要修訂；真正準備公開時才集中確認公開版本。

- **可驗證主張**：日期、版本、數字、引文與因果是否有依據；把「我這次的感受」保留為個人經驗，不自動擴為普遍結論。心情不需要證明，涉及外部事實的句子仍可核對。
- **第三人與脈絡**：材料是否包含作者不願公開的細節、依賴私下情境或容易讓讀者誤認的轉述。只是辨識相關問題，不為每篇文新增固定審核問卷。
- **素材來源**：有引用或外部圖片才檢查出處與使用標示，來源與授權分開。
- **閱讀與媒體**：依文體維持語意結構、連結可理解、圖片具適當替代內容；技術操作交代前置條件與重要失敗情況。
- **搜尋與維護**：作者在意搜尋才處理搜尋需求；會過期的技術內容交代適用時間與版本，不為營造新鮮感改寫原始日期。
- **網站交付**：文章檔案、預覽、候選驗證與正式發布沿用對應 skill；新入口的內容確認不等於發布授權。

## 六、文件與流程分工的建議

文章設定與續寫狀態沿用現有 PROJECT 或任務文件；術語才進該寫作專案的 CONTEXT。不要把每篇文章的讀者、情緒或自訂詞寫進網站根目錄的工程詞彙表。跨次寫作需要保存脈絡，但普通陪聊不應為產生文件而中斷。

現有寫作參考對獨立寫作專案要求 CONTEXT 與 PROJECT；若要採用「有詞彙才建立 CONTEXT」及更輕的文章紀錄，需要在正式設計時明確調整此條，不能讓兩份有效指令互相衝突。是否使用新資料夾、如何避免進入公開網站輸出、frontmatter 是否增加欄位，都尚未決定；本研究不新增要求。

工程入口繼續處理功能、程式碼、網站行為與工具維護；文章入口處理創作探索。若寫作時發現需要新的 renderer 或版型功能，抽出工程需求處理，已可寫的內容可以繼續。新 skill 的實作仍依既有工程管線交付；不把它的 spec／測試流程逐篇施加給所有抒情稿。

## 七、日後應驗證的案例

以下是評估方向，**不是已核准測試計畫，也沒有測試通過結果**。

| 案例 | 可觀察的預期行為 |
|---|---|
| 「今天很煩，只想寫爽的」 | 接住表達，不要求受眾、教學成果或詞彙表，不補勵志結尾 |
| 「不知道要寫什麼，但這句話一直在腦中」 | 從原句探索，可開始試寫，未知目的不阻擋 |
| 有讀者設定的技術教學 | 查出會影響理解的先備知識、名詞與前置條件 |
| 技術心得混合生活敘事 | 只對事實主張核對，保留其餘敘事自由 |
| 「自由」是刻意多義的散文 | 不強制標準定義，不以領域詞義衝突否決 |
| 「只聽我說，不要幫我改」 | 不自動組稿、評分或反駁 |
| 作者要求嚴格挑戰論點 | 可以深入追問證據與替代解釋，作者保有立場決定權 |
| 中途由抒情轉成教學 | 只補影響新方向的資訊，不重問已確認內容 |
| 恢復舊稿 | 沿用已有設定與術語，不重開完整訪談 |
| 想發布含第三人或外部素材的文字 | 在公開前處理相關細節，不把起稿當成發布授權 |
| 只是改程式或一般對話 | 不誤觸文章訪談 |

尚無證據證明這套入口會提高文章品質、降低時間或保住作者聲音。驗證需比較真實互動與作者回饋，分清本 agent 自檢、獨立評估與實際使用者接受；不能只查 SKILL.md 關鍵字就宣稱有效。

## 八、待正式設計時決定

1. skill 名稱與明確觸發；預設自由聊已由使用者決定，不重問。
2. 文章脈絡的儲存位置、何時保存，以及 CONTEXT 的按需建立與既有規則如何一致。
3. 是否讓完整文章訪談只在明示要求時進入；普通撰稿不強迫先完成訪談。
4. 與兩個 runtime、現有 canonical 套件與 materializer 的包裝方式。
5. 工程／文章流程的正式 routing 文件與最小代表案例。

這些尚未定案，不影響本次研究結論：新增文章入口有價值；需要改編的是互動與完成契約，術語原則可選用，無須改寫原本工程技能。
