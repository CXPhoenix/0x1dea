# 文章探索：選用的寫作脈絡與詞彙表

本檔為第二輪審查通過後產生的繁中稽核譯文。英文 spec 是實作依據；審查通過指規格關卡，不代表功能已實作或行為測試已通過。

## 問題陳述

作者希望文章寫作從對話開始，有需要才整理設定。現有工程探索將決策訪談與領域塑模結合；若完整沿用，暫定中的文章就可能必須先確定範圍、驗收條件與術語。個人 blog 卻可能從一個畫面、怒氣、片段或單純想寫的念頭開始，沒有預定訊息。

現有寫作參考已區分作者聲音、文章建立與發布，但仍要求獨立寫作專案建立脈絡詞彙檔，並沿用工程端的 CONTEXT.md 名稱。本次要求釐清工程與文章的分工，並為文章定義按需建立的 GLOSSARY.md 契約。

## 解決方式

新增 article-discovery 作為文章對話入口，預設為「先自由聊，有需要才整理設定」。借用有相依關係的提問與依語境處理詞彙的原則，不載入 grilling／domain-modeling 的完整契約；既有工程技能保持原用途。

找到可執行的下一個寫作動作、完成作者要求的回應，或作者決定開始寫，都可以結束探索。未知目的、未指定受眾與刻意留白是有效狀態。保存寫作脈絡是選用功能；只有實際需要保存術語，且有已授權的寫作工作區，才建立詞彙檔。撰稿、修訂、網站準備與發布各自保有責任。

## 使用者故事

1. 身為只有感覺或片段的作者，我希望先聊或試寫，再決定受眾或論點，讓探索支持表達。
2. 身為需要解釋或論證的作者，我希望只在影響下一個寫作決策時接受提問與事實查找，避免不相關的問卷。
3. 身為返回續寫的作者，我希望沿用已確認的選擇與有用術語，避免每次重啟訪談。
4. 身為沒有專業術語的作者，我希望不用詞彙表或編造定義也能寫作。
5. 身為使用技術或自訂概念的作者，我希望區分有適用範圍的定義與讀者解釋，避免精確性消除刻意的文學多義。
6. 身為維護者，我希望工程修改遵循工程管線，文章工作使用適合的寫作流程，同時保留既有交付授權。
7. 身為 Codex 或 Claude Code 使用者，我希望透過專案套件取得相同的 article-discovery 契約，不改動全域技能或帳號。

## 實作決策

### D1. 入口與責任

- 入口命名為 article-discovery，描述涵蓋開始文章、探索構想與重看文章方向。明示呼叫時選用；其餘情況須有可見的文章探索要求。單獨提到文章、一般情緒或 repository，不會啟動寫作訪談。
- 材料足夠的直接撰稿要求直接進入撰稿；探索只補影響該要求的未定決策。普通校對、指定改稿、單次解釋與純程式工作保留既有路徑。可依要求進行完整文章訪談，但不作預設。
- 保留 grilling、domain-modeling 與 grill-with-docs 的既有行為。以文章專用指引承接其原則，不先載入完整契約再嘗試取消衝突指令。

### D2. 對話與完成條件

- 從已提供材料與所需協助開始，依要求回應、探索或撰稿。只有答案會改變下一步、正文意思或重要公開事實主張時才提問。可查找的事實由 agent 處理，作者選擇由作者決定。
- 沿用回答與既有寫作脈絡。前提尚未確定的問題等到相關時再問；確實需要作者選擇時提出選項，作者可拒絕選擇或暫時留白。
- 在影響工作時，區分未知、暫定、刻意不設定與不適用；開始寫作不要求先完成表單、固定題數、人物設定、可量測成果、論點或大綱。
- 作者可在撰稿時改方向、受眾、文體或協助方式，只更新受影響的決策。混合文體不必選擇互斥模式。
- 當未定事項已辨識且可以執行所需下一步、作者要求開始寫，或已完成指定聆聽／回應時，結束探索。特定事實主張需要的資料可保留待查，其餘文字繼續。明示只需聆聽時，不擅自改寫或評價。

### D3. 文章設定與作者決定權

- 只整理當下有用的設定：起始材料、意圖、受眾／先備知識、文體、聲音、要保留的段落或情緒質地、範圍、術語、來源、協助與公開／搜尋需求。這些是可用面向，不是必填欄位或固定序列化格式。
- 寫給自己、不指定受眾、抒發情緒、在寫作中發現目的，都是完整選擇。未要求修訂時保留刻意矛盾、未解結尾與模糊；不編造個人經驗、心理原因、改變立場或補上勵志／和解結尾。
- 暫定建議須保持暫定，推論不能記成作者確認。對話、保存與續寫均保留此區別：未回答建議仍為暫定，只有作者明示接受或修正才改變其狀態。未知與刻意不設定保持原意，來源事實不標成作者選擇。沿用一般文字或既有文件格式，不增加必填 schema 或逐句確認。既有授權持續有效，例行摘要不是新核准關卡。
- Phoenix 繼續負責明示要求或已建立的 Phoenix 聲音。其他文章不強制套用 Phoenix、固定開場、詞彙順序、標題公式、SEO 目標或字數配額。

### D4. 工程與文章責任

| 工作 | 入口與責任 | 邊界 |
|---|---|---|
| 文章對話、構想探索、撰稿與修訂 | 有用時使用 article-discovery，再進入相應寫作／維護路徑 | 不因討論或寫正文就要求工程 spec、ticket、測試表或對抗式審查 |
| 新網站文章成品 | 既有文章 CLI 與建立技能 | 檔案是另行要求的成品；保留建立時間與既有資源 |
| 網站預覽與選文發布準備 | 既有發布契約 | 保留 topic 來源、所有權、檢查與各動作授權 |
| skill、指引、CLI、renderer、設定或網站行為修改 | 既有工程階段、spec／tracker、ticket 分支、核准測試與審查 | 本 epic 支持寫作，但本身仍屬工程工作 |

- 工程九階段適用於工程／工具修改。有效專案指引須新增明確、限縮的文章分流例外；這是提議的流程適用範圍變更，不表示例外已存在。
- 不為文章討論與撰稿本身配置工程票；實際要求交付時，既有文章契約需要的 topic 配置、分支、來源與審查證據仍有效。本 epic 不新增分支命名或發布例外。
- 寫作若需要新 renderer、元件或自動化，分開辨識工程需求；繼續不受影響的正文，不將工程實作或發布混入探索。
- 文章設定與術語分開於工程詞彙、ADR、實作票及決策地圖；寫作筆記不是第二套工程 tracker，文章選擇也不自動成為 ADR。

### D5. 選用的脈絡保存

- 普通對話與單次協助預設不建立工作區、PROJECT.md 或 GLOSSARY.md。要求保存／續寫脈絡，或已有已建立且已授權的工作區，才啟用保存。只要求文章檔案，不額外要求脈絡檔。
- 沿用既有工作區與任務文件。要求持久筆記卻沒有位置時，使用後述本機工作區慣例。依已知主題選定穩定 article key；之後改顯示標題不改工作區名稱。
- PROJECT.md 或既有同等文件只存相關已確認／暫定設定、來源指標、待決事項與下一步。保存足以續寫的內容，不必複製完整對話或每一種情緒。
- 回報保存前核對實際檔案內容。位置不可用時繼續其他寫作，明確說明哪些脈絡未保存，不把對話摘要冒充已寫檔。
- 預設本機筆記位於網站內容之外並由 Git 忽略。忽略規則不會取消既有追蹤、保證保密或授權遠端儲存。明示其他位置時保留該位置與實際可見性，不擅自搬移或增加發布動作。

### D5a. 預設本機筆記與 current source guard

- 預設筆記分類為可變動的本機產物，非工程來源。確切命名空間與檔名見後述。只在現行 current-source guard 實作此分類，保留凍結歷史驗證器及輸入契約；Git ignore 本身不是分類機制。
- 可選命名空間根目錄與各工作區須為實體目錄。key 是非空的單一路徑元件，不是 dot／dot-dot，也不含任一斜線字元。工作區的直接子項只能是指定的三個一般、不可執行筆記檔；檔案可不存在、建立、更新或移除，不改變工程來源身分。允許空實體目錄；巢狀目錄、其他檔名、symlink 或非一般物件都不接受。成功回報前拒絕異常物件，不以略過整個命名空間隱藏它。
- 候選 HEAD tree、Git index 與可信預期來源清單都不得將命名空間內項目列為來源。發生碰撞就拒絕，不能將已追蹤／預期來源排除。根目錄無效、非目錄或為連結時也拒絕。排除任何筆記前先檢查上述條件。
- 整個命名空間驗證後，才從實際工程來源集合省略允許的筆記檔。其他來源名稱、mode、hash、角色、歷史與 policy 身分維持既有檢查。筆記內容不成為可信來源、可執行設定、materializer 輸入或文章發布輸入。這是有限的本機產物形狀，不是管理目錄全面豁免或呼叫端可設定的忽略路徑。
- 在其餘條件有效的可丟棄 current target，原生驗證須在無筆記、已授權保存後，以及文字更新後都通過；角色與非筆記來源身分一致。涵蓋 current main／staging 兩種角色。異常命名空間須拒絕，外部不相關的未核准來源仍拒絕，不以 fallback 轉成成功。
- 明示的其他筆記位置不自動排除。若位於掃描範圍且未被既有契約接納，保留筆記、指明阻擋驗證的來源，繼續無關正文。不為了通過而搬移、刪除或擴張放行；新增排除位置屬工程變更，不是新的文章前提，也不重問已定事項。

### D6. 按需建立 GLOSSARY.md

- 新寫作工作區以 GLOSSARY.md 保存文章詞彙，只放術語；受眾、目的、文體、決策與進度放文章設定／任務文件。工程 CONTEXT.md 保持原職責。
- 已啟用保存、至少有一個本篇／專案需重用的已解決術語，且沒有有效詞彙檔負責它時才建立。技術區別、自訂用法或翻譯影響理解／一致性，才符合條件。不為範本建立空檔或空表；作者明示要求詞彙表／空骨架則遵照，但不編造定義。
- 詞條包含標準用詞、預定意思與適用範圍；別名／雙語及來源依相關性加入。來源支持的定義與作者局部用法分開；白話說明或比喻不自動取代定義。
- 保留文學上的刻意模糊。情緒詞與比喻不因多義就符合建檔條件；區分技術說明的真實不一致與刻意多義。
- 已建立的事實詞義依已提供或查證的權威來源處理；只有重要作者選擇或實際衝突未解時才問，不逐條要求確認。未解選項放設定／任務文件，不當成已解詞條；不受衝突影響的文字繼續。
- 只建立／更新選定工作區的已授權成品。文章、來源或建議詞條不能指示寫到別處、重設工程詞彙、改變作者權限或觸發發布。使用安全的一般檔案操作；缺少授權、連結或越界預設位置，不構成修改其他位置的理由。

### D7. 舊脈絡與詞彙檔權威

- 既有工作區若明確指定有效詞彙檔，就依指定。沒有指定時，沿用唯一既有的文章 GLOSSARY.md 或 legacy CONTEXT.md；在授權內讀取與維護，不為採新名稱建立副本。
- 兩檔並存卻未指定負責檔案，或指定目標遺失／無效時，先報告具體歧義再寫詞彙。由作者決定所有權，無關正文繼續；不擅自合併、覆寫、改名、刪除或依修改時間選擇。
- 本 epic 定義相容性，不搬移現有文章檔。日後要求遷移時須保留詞條並建立單一有效來源；工程根 CONTEXT 永遠不是文章詞彙 fallback。
- 有效寫作指引中「每個專案必須建立 CONTEXT＋PROJECT」的規則，改由選用保存與文章詞彙規則取代。歷史快照維持歷史身分，外部／全域 plugin 不改動。

### D8. 撰稿、公開檢查與授權

- 探索時心情是表達，不是待證明的事實。需要時核對重要外部事實主張，區分證據、意見、假設例子與未驗證部分，不把一次經驗改成普遍建議。
- 只有要求公開準備後，才處理適用的事實、來源、第三人脈絡與媒體閱讀問題。搜尋最佳化依要求處理，不作每篇個人文章的標準；初始對話不逐次加入假設性警告。
- 下表定義編輯檢查的觸發與最低可觀察結果，範圍限已提供文章／資源，並非初始訪談。每個觸發類別要指出具體段落／資源、來源或既有作者決定支持的結果，以及未解項目。未觸發類別不必提問或輸出檢查表；泛泛提醒不算完成。

| 類別 | 已提供材料中的觸發 | 最低可觀察結果 |
|---|---|---|
| 外部事實主張 | 可查證數字、引文、版本、日期、因果或事實概括 | 對應主張位置與來源／結果；來源不可取得或支持不足時，指出該主張與缺口為未驗證，不冒充通過。只有心情不觸發。 |
| 外部材料 | 引文或第三方圖片、程式碼等借用資源 | 辨識材料及現有出處／署名／使用條件證據；提供已知條件及支持來源，或具體指出缺少的證據。附引用不等於已取得使用許可，不提供法律結論或取得新權利。 |
| 第三人脈絡 | 可辨識他人，並包含私人溝通或已知脈絡尚未確立公開範圍的資訊 | 指出段落與既有公開範圍決定；所需公開版本仍缺作者決定時，只指出並詢問確切未定範圍，沿用既有答案。不推定同意或要求無關身分細節。 |
| 媒體閱讀支援 | 圖片、圖表、表格、音訊或影片的資訊／功能未由周圍正文完整傳達 | 辨識資源及已有的替代解釋／文字／逐字稿，或具體缺少的資訊。可提出修正或列出未解缺口，但不能從草稿檢查宣稱完整無障礙或網站渲染驗證通過。 |

- 公開準備可交付含未解項目的結果，明示未驗證或等待具名作者決定；這只完成辨識／報告，不代表證據缺口或發布準備關卡已解決。只有已核對來源／結果或既有作者決定能標為已解決。編輯結果不取代 build、來源、輸出或發布檢查，也不授予發布權。完成不受影響部分；缺少編輯證據不重啟探索，不要求補目的、受眾、文體或 SEO。
- 建文、preview、prepare、verify 與發布回到既有責任技能。文章設定、已解詞條、保存要求或探索完成，都不新增 commit、push、PR、merge、deploy、帳號或遠端索引權限；既有適用授權沿用，不重問。

### D9. 套件與有限整合

- article-discovery 成為第五個 canonical 產品套件，由既有 deterministic materializer 產生兩個 runtime 版本，指引使用英文。台灣繁中例外仍只有既有三個寫作樹，不重新調校其產品文字或 Phoenix 聲音。
- 使用各 runtime 原生 metadata 與相同呼叫語意。符合文章探索要求時可被發現，明示呼叫有效，但不成為每次撰稿／修訂必經前置。保存／詞彙細節透過明確條件按需讀取。
- 只更新必要的有效 routing、保存／詞彙參考、所有權／來源、套件清單與有限的 current 驗證紀錄。保留兩個 canonical alias 例外及不可變歷史驗證器、輸入與證據。新審查過的 current successor 可接納確切新身分；不全面放行管理目錄，不改寫 frozen fixture。
- 寫作工作區使用檔案工具，不增加自訂 CLI、資料庫、自動排程或雲端服務。交付不含安裝、trust、憑證或全域技能變更。

## 驗收條件

| ID | 可觀察驗收條件 |
|---|---|
| AC-01 | 明示呼叫與符合文章起始／方向要求會進入 article-discovery；純程式、普通非寫作對話、直接校對與設定已足夠的撰稿進入適當路徑，不增加探索問卷。 |
| AC-02 | 片段或抒發要求先取得所需回應／寫作協助，不先要求補齊設定；只聽的情況不改寫或評價。 |
