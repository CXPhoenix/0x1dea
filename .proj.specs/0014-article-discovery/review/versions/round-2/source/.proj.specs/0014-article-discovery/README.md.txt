# article-discovery 規格草案

日期：2026-10-24。階段：已依第一輪結果修訂，待第二輪獨立對抗式審查；尚未建立 ticket、實作 skill 或執行新技能的行為測試。

- [英文規格](spec.en.md)：實作的唯一規格來源。
- [追溯矩陣](traceability.md)：48 列需求組合，對應 17 項驗收條件與提議的驗證情境。
- [第一輪審查](review/round-1.md)：保留原始結果與凍結來源，修訂不回寫歷史結論。
- [前期研究](../_discovery/article-writing-entry/research.md)：來源、限制與設計理由；其中暫議的文章 CONTEXT 名稱由本草案的 GLOSSARY 規則取代。

已確認的方向是「先自由聊，有需要才整理設定」。沒有預定目的、受眾、論點或名詞表，都可以開始寫；明示需要深入訪談時才提高討論強度。

本草案釐清的主要分工：

| 項目 | 規則 |
|---|---|
| 工程流程 | skill、CLI、renderer、設定與網站行為修改仍走工程九階段；本 epic 也屬工程維護 |
| 文章流程 | 自由聊、探索、試寫與修訂不必先產生工程 spec／ticket／測試表；實際來源分支與發布仍依既有交付契約 |
| PROJECT.md | 需要保存／續寫脈絡時才建立或沿用，放文章設定、來源指標、待決問題與下一步 |
| GLOSSARY.md | 已啟用保存，且有至少一個需要重用的已解決術語時才建立；沒有術語就沒有空檔，也不編造定義 |
| 預設保存位置 | 新的持久工作區提議使用 `.proj.writing/<article-key>/`，位於網站內容之外並由 Git 忽略；一般陪聊不建立它 |
| 筆記與 current guard | 只將指定形狀中未追蹤、非連結、不可執行的三個筆記檔名分類為本機產物；額外檔案、巢狀目錄及已追蹤／預期來源碰撞仍拒絕，不整個目錄放行 |
| 既有文章 CONTEXT.md | 沿用既有有效詞彙檔，不自動改名、搬移或刪除；遇到兩份未指定權威的詞彙檔，先釐清詞彙寫入位置，不阻擋其他寫作 |
| 工程 CONTEXT.md | 維持工程用途；文章名詞、受眾與心情不混入此檔 |
| 作者聲音與發布 | Phoenix 仍依既有觸發；內容討論完成不等於 build、預覽或正式發布通過 |

儲存位置、第五個 canonical 套件與文件整合範圍是本草案提出的具體設計，仍待審查；使用者已同意方向不代表這些細節已通過驗證。

本輪另補齊：公開前檢查的觸發與最低結果；單一未指定 GLOSSARY 的直接沿用；對話、保存與返回時的暫定／確認狀態保留。公開檢查不成為起稿問卷，未解項目如實列出，不冒充驗證通過。

依專案語言規則，完整 `spec.zh-TW.md` 在對抗式審查通過後才產生並綁定英文 Git blob hash。本頁僅供導覽與摘要。
